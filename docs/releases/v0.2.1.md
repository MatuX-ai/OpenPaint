## 1. 问题描述

v0.2.0 的 GitHub Actions Release workflow（run #26）9 分 38 秒跑完后，
GitHub Release 页面 [https://github.com/MatuX-ai/OpenPaint/releases/tag/v0.2.0](https://github.com/MatuX-ai/OpenPaint/releases/tag/v0.2.0)
的资产列表 **完全为空**。直接 curl `release-v0.2.0.json` 返回 `404 Not Found`。

下载用户报"看不到 .msi 文件"，影响了 W12 上线后的下载体验。

## 2. 根因诊断

`.github/workflows/release.yml` 的 `publish-release` job 使用了精确路径 glob：

```yaml
files: |
  artifacts/openpaint-windows/*.msi
  artifacts/openpaint-windows/*.exe
  artifacts/openpaint-macos/*.dmg
  artifacts/openpaint-macos/*.deb
```

`actions/upload-artifact@v4` + `actions/download-artifact@v4` 在解压后
会把文件放在 `artifacts/<artifact-name>/<original-subdir>/<file>`，
但不同平台 artifact name 不同（`openpaint-windows` / `openpaint-macos`），
且具体子目录取决于 tauri 的 bundle 路径。`softprops/action-gh-release@v2`
的 `files:` glob 在这种嵌套结构下未能匹配到任何文件，但因为没有开启
`fail_on_unmatched_files`，整个 step silent fail，导致发布为空但
workflow 仍报 success。

## 3. 修复

`release.yml` 改用 `**` 递归匹配，兼容 artifact 解压结构：

```yaml
- name: List collected assets (with full filenames)
  run: |
    echo "=== Tree ==="
    find artifacts -type f \( -name "*.msi" -o -name "*.exe" -o -name "*.dmg" -o -name "*.deb" -o -name "*.app" \) | sort
    echo "=== Sizes ==="
    find artifacts -type f \( -name "*.msi" -o -name "*.exe" -o -name "*.dmg" -o -name "*.deb" \) -printf "%p  %s bytes\n" | sort
    echo "=== Full ARTIFACTS DIR TREE (W15 G6 debug) ==="
    ls -laR artifacts/ || true

- name: Publish draft release
  uses: softprops/action-gh-release@v2
  with:
    tag_name: ${{ github.ref_name }}
    draft: true
    generate_release_notes: false
    # W15 G6 修复：用 ** 递归匹配，兼容 actions/download-artifact@v4
    # 解压结构（不依赖具体 artifact 子目录名）。同时把 .deb / .app.zip
    # 也纳入（mac .app 是目录，需要 zip 包装才能 attach）。
    files: |
      artifacts/**/*.msi
      artifacts/**/*.exe
      artifacts/**/*.dmg
      artifacts/**/*.deb
    # .app 是目录，不能直接 attach；用 zip 包装（先忽略）
    fail_on_unmatched_files: true
```

**策略**：

1. 用 `**` 递归匹配 — 不依赖具体 artifact 子目录名
2. `fail_on_unmatched_files: true` — 暴露 silent fail，下次 CI 会立即报错
3. List 步骤细化为 Tree / Sizes / Full Dir Tree 三段，便于排错
